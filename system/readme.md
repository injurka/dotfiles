# Системные настройки injurkapc

Экспериментальный обход сбоя сна на X870E AORUS PRO X3D с AMD Navi 48.
Ядро остаётся текущим; успешное пробуждение ещё не подтверждено.

Журналы показывают сбои `deep` 29 октября и `s2idle` 30 октября 2026 года.
Новая конфигурация использует одну попытку S3 (`SuspendState=mem`,
`MemorySleepMode=deep`) и последовательное восстановление устройств
(`pm_async=0`). Это может увеличить время перехода в сон и пробуждения.
`pm_debug_messages=1` и `pm_print_times=1` добавляют диагностику.
Настройки гибернации отдельные. Не устанавливать на другие компьютеры.

Установка с проверкой исходного файла и резервной копией:

```sh
sudo python3 /home/injurka/my/dotfiles/system/install-suspend-workaround.py
```

Установщик применяет параметры сразу, выводит путь резервной копии в
`/var/lib/dotfiles-suspend-workaround/` и точную команду отката.
Откат проверяет, что файлы не были изменены после установки.
`tmpfiles.d` восстанавливает параметры после перезагрузки; systemd читает
настройку сна при следующем уходе в сон. Перезагрузка для применения не нужна.

Перед проверкой сна сохранить работу. После пробуждения проверить:

```sh
journalctl -b -k --no-pager --grep='PM:|amdgpu|suspend|resume'
cat /sys/power/pm_async
cat /sys/power/mem_sleep
```

Ожидаемые параметры: `pm_async=0`, `s2idle [deep]`. Это подтверждает
настройки, но не исправление: нужен реальный цикл сна и пробуждения.

Механизм pm_async описан в документации ядра:
https://kernel.org/doc/html/latest/admin-guide/kernel-parameters.html
